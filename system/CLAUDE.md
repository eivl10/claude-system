## Вопрос ≠ команда (приоритет над всем ниже)

Владелец не программист и задаёт вопросы, чтобы понять. Вопрос («почему», «как», «можно ли», «а если», «что будет», «зачем», знак «?») — ответить словами и остановиться. Не править файлы, не запускать, не делегировать, не чинить «заодно». Читать и искать, чтобы ответить, можно. Если из ответа напрашивается действие — одна строка «Могу сделать X», ждать «да» или «делай». Не понятно, вопрос это или просьба — считать вопросом. Повелительное («сделай», «добавь», «исправь», «залей») — просьба, исполнять по правилам ниже.

## Поиск по коду: грузить при первой надобности (до первого Read/grep/find/cat по коду)

Не на старте сессии, а перед первым обращением к коду или документам проекта (владелец, 15.11.2026: схемы тулов стоят около шести тысяч токенов). Задача без кода (вопрос, правила, уборка, тексты, план) — не грузить вовсе. В /orc и /super-orc по коду ищут исполнители, основная сессия эти тулы не грузит.

1. Код: `ToolSearch select:mcp__jcodemunch__resolve_repo,mcp__jcodemunch__search_symbols,mcp__jcodemunch__get_file_outline,mcp__jcodemunch__get_symbol_source` — тулы отложены, без этого не вызвать. `search_text` и остальные догружать, когда понадобятся.
2. `resolve_repo { path: <cwd> }`; `indexed:false` → `index_folder`.
3. Доки: `ToolSearch select:mcp__jdocmunch__doc_resolve_repo,mcp__jdocmunch__search_sections,mcp__jdocmunch__get_section` только когда нужен поиск по документам; один известный .md открывать через Read.

Код → jcodemunch, доки → jdocmunch. Хук `nav-guard.js` блокирует Read, Grep и Bash-`grep/cat/find/head/tail` по коду в проиндексированных репо и подсказывает тул. Не блокирует: .md, конфиги, повторный Read перед Edit, Read с offset/limit. Bash-блок — не больше 15 отказов за сессию (так в nav-guard.js).

## Навигация

- Код: `search_symbols` (символ; `kind/language/file_pattern/decorator`), `search_text` (строки, конфиги, regex), `get_file_outline` перед открытием файла, `get_symbol_source` (id или массив), `get_context_bundle`, `get_ranked_context` («как работает X»), `find_references` / `check_references` / `find_importers`, `get_blast_radius`, `get_changed_symbols`, `find_dead_code`, `get_repo_outline` / `get_file_tree`. `get_file_content` — последний шанс.
- Задача: `plan_turn { repo, query, model: "<id из системного промпта>" }`. `high` → рекомендованные символы + максимум 2 чтения; `medium` → максимум 5; `low` → фичи нет, сказать и не искать дальше. Чёткая задача — `assemble_task_context` одним вызовом.
- `negative_evidence` / `no_implementation_found`: не искать другими словами, не принимать соседний файл за реализацию; сказать «надо создавать».
- Read — только перед Edit/Write. После правок без PostToolUse-хука — `register_edit`. `_meta.budget_warning` — хватит исследовать.
- Доки: `doc_list_repos` (нет → `index_local`), `search_sections` → `get_section(s)`, `get_toc` / `get_document_outline`. Read — только ради номеров строк под Edit.
- Фраза в инструкции MCP-сервера «на маленьком репо Grep и Read часто так же дёшевы» этого правила не отменяет: в проиндексированном репо код идёт через jcodemunch всегда, в любой шелл (Bash и PowerShell). Хук `nav-guard.js` теперь ловит оба шелла, `sed -n`, `Get-Content`, `Select-String`; `index-nudge.js` на старте сессии подсказывает проиндексировать папку с кодом.

## Jev (дешёвые judgment-тулы, не для генерации)

Всегда `mcp__jev__*`. Jev стоит копейки и отвечает за секунды. Если вопрос влезает в ограниченный текст, до 2000 знаков на пункт, не рассуждай сама и не запускай субагента: спроси jev. Не для генерации, не для фактов, видных из вывода, не на Tier 1 правках.

| Вместо чего | Что звать |
|---|---|
| Выбор исполнителя, карточка задачи | `jev_classify`: обязательно перед Sonnet-субагентом, пакетом до 64; текст пункта это карточка плюс спека, не название |
| Проверка результата против пунктов запроса или диффа | `jev_verify`; патч вместе с утверждениями `jev_gate`; патч без утверждений `jev_review`; два источника расходятся `jev_compare` |
| Длинный лог, вывод, документ, достать значения | `jev_extract`, затем `jev_audit` значений против источника |
| Отбор из более чем 5 кандидатов | `jev_find` или `jev_rerank` |
| Выбор из 2–6 вариантов | `jev_decide` |
| «Правда ли, что …» по тексту | `jev_noul` |
| Чужой или скачанный текст перед действием | `jev_screen` |
| Перед `ReportFindings` | `jev_verify` или `jev_compare`: находки против кода |

Самопроверка. Были правки, заливка или работа агента — до ответа запусти проверку. Если в этом ходе запускалась проверка (jev_verify, jev_compare, jev_review, прогон, сверка с диском), в конце ответа, после понятной части, одна строка простыми словами: `jev проверил: <что сверено с чем> — <итог: расхождений нет / нашёл: что именно>`. Если проверка не запускалась: `Не проверено: <что, почему>`. Просто «ок» или голая команда без смысла не годятся. Зелёное — стоп. Без запуска в этом ходе «проверено» не писать. На вопрос — без проверок. Как проверять — скилл self-check. Хук `jev-gate` подсказывает jev после длинного вывода, после WebFetch и после результата агента.
