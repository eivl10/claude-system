# Design Library — Index

Личная библиотека дизайн-вкуса пользователя. Не абстрактные принципы — конкретные, проверенные на реальных проектах паттерны (значения CSS, код, что отклонено и почему). Глобально, не привязано к одному проекту — вкус переносится между проектами.

Источники: "партнерский кабинет 4" (админ-панель), Космоскай "Интенсив по ритму с Алексом Ксено" (лендинг). Оба проинд ексированы в jdocmunch — искать через `search_sections` по теме, не читать файлы целиком.

## По тегам

**landing / marketing** → `landing-patterns.md`
- Живой фон / animated blobs
- Bento grid (асимметричная сетка)
- Glassmorphism / стеклянные карточки
- Marquee / бегущая строка
- Встроенный видео-плеер
- Anti-pattern: отказ от "ИИ-шности" (pill-бэйджи, градиентный текст, глянцевые кнопки — избегать)

**ai-stamps / что читается как «сделано нейросетью»** → `ai-stamps.md` (каталог штампов: форма и радиусы, layout, цвет и шрифт, движение, копирайт, контент; внизу «Промпт-блок» для агентов). Правило: `~/.claude/rules/ai-stamps.md`. Режим Космоскай (`landing-patterns.md`) каталог не трогает.

**admin-ui / dashboard** → `admin-ui-patterns.md`
- Date-range picker (фильтры)
- DatePicker внутри drawer (withPortal)
- Чекбокс-фильтр с accentColor
- CSS-переменные палитры (--ink-soft, --accent)
- Правило: drawer не трогать структурно при точечных правках

**page-assembly / готовые шаблоны** → skill `landing-page-builder` (обобщённая структура секций + JS-паттерны из ТЗ Космоскай)

## Как пополнять

Новый кейс — если понравившееся решение подтверждено на реальном проекте (не гипотеза), добавить в соответствующий файл тем же форматом: название → конкретная реализация (значения, код) → что делает это выбором, а не дефолтом. Если тема новая — новый файл + строка сюда.
