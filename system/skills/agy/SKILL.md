# agy: правила вызова

Маршрут (что кому, agy по умолчанию) — в CLAUDE.md, раздел «Делегирование». Здесь только техника.

## 1. Перед первым вызовом в сессии

1. **Авто режим.** Сначала просто запустить agy: в `autoMode.allow` есть `Bash(agy:*)`, 07.10 запуск проходил. Если классификатор заблокировал вызов, одной строкой попросить владельца: «Отключи Авто режим, в нём agy не работает». Ждать ответа. Режим самому не переключать (`disableAutoMode` не трогать). После подтверждения в сессии повторно не просить.
2. **Модель одна: `gemini-3.8-flash-high`.** Всегда `--model gemini-3.8-flash-high`. `flash-medium`, `flash-low` и модели Claude/GPT в agy не использовать (решение владельца 20.10: Claude и GPT из agy уходят, останется Flash; low и medium тупят).
3. **Квоту не проверять.** Предполётный квотный гейт в `agy-wrapper.sh` выключен по умолчанию (включается `AGY_USE_GATE=1`). Gemini почти без лимита, а API квот теперь отдаёт только группу Claude/GPT, и гейт принимал отсутствие данных за «квоты нет» (код 78). Решает реальный отказ: 429 или `Individual quota reached`. Тогда в режимах /orc и /super-orc переключить профиль по п. 4, а в обычном режиме одной строкой сказать владельцу и перейти в «Соло» по CLAUDE.md. Если снова код 78 с «[agy-gate] BLOCKED»: оболочка держит старую функцию из снапшота, запустить `AGY_SKIP_GATE=1 agy ...` и сказать владельцу перезапустить сессию.
4. **Переключение профиля.** В режимах /orc и /super-orc сама, без «да» (решение владельца 21.10.2026), но только при реальном отказе (код выхода сторожа 75, 429 или `Individual quota reached`) и при закрытом Antigravity GUI: `tasklist | findstr /i antigravity` пусто, иначе keyring перезапишется обратно. Открытый GUI не закрывать. Номер — следующий по кругу после активного (`%USERPROFILE%\.agy-profiles\cred-active.txt`, профили — файлы `cred-<N>.bin` рядом). Команда `cred-switch.ps1 <номер>` из `<VIBECODING>\Claude\AGY-sub\`. Затем тот же бриф запустить заново новым разговором, перед этим проверить по диску, что уже записано. Все профили дали отказ или GUI открыт — «Соло» по CLAUDE.md. В обычном режиме — только после «да» владельца (одно «да» = одно переключение). Откат — `cred-switch` на прежний номер. Исключение (20.10): при доработке и проверке самой программы AGY Switch переключать можно без «да» и без бэкапа; GUI проверять самой, открыт — галочка в программе закрывает и снова открывает Antigravity. Состояние профилей и квот нигде не записывать (ни в память, ни в доки, ни в HANDOFF): оно временное.
5. Обёртка `agy-wrapper.sh` в Git Bash при 429 сама переключает профиль (реактивная ротация) — это свойство программы AGY Switch, отдельное от правила п. 4. Сторож `agy-run` обёртку не использует, профили не переключает и 429 в потоке событий не ищет. Если функция `agy` не грузится (`_agy_resolve_bin: command not found`) — звать `<HOME>\AppData\Local\agy\bin\agy.exe`; автопереключения профиля тогда нет.

## 2. Вызов: сторож agy-run (по умолчанию)

Бриф пишу в файл, сторож запускаю в фоне (`run_in_background`), по выходу приходит сводка до 12 строк. Часового лимита нет: сторож останавливает агента, только когда нет движения. Он сам добавляет к брифу хвост (отчёт в файл за 30 с, без серверов и повторов), ставит `--add-dir` и `--mode accept-edits`, ставит запуск в очередь по памяти и один раз повторяет мгновенное падение.

```bash
node <VIBECODING>/Claude/AGY-sub/agy-run.js --name <slug> --brief "<абс. путь бриф.md>" --dir "<абс. корень проекта>" [--dir "<ещё>"] [--report <файл отчёта>] [--out-dir <папка логов>]
```

Голая команда без `cd ... &&` и присваиваний впереди, пути абсолютные и ТОЛЬКО с прямыми слешами `/` в кавычках: Bash-тул (Git Bash) съедает `\`, и запуск падает с «Cannot find module» (27.10.2026). Логи и итог по умолчанию в `<первая --dir>\docs\tmp-agy\<name>.*` (`summary.json`, `events.jsonl`, `answer.md`, `stderr.txt`). Бриф до 28 000 символов; больше — детали в файл и путь к нему в бриф.

Остановка по движению, пороги в минутах (флаги на задачу):
- `--idle 6`: ни одного события.
- `--tool-max 20`: одна команда висит (долгая сборка или деплой: `--tool-max 60`).
- `--effect 15`: события идут, файлы не пишутся (исследование без записи: `--effect 40`).
- `--loop 6`: одно и то же действие подряд, раз.
- `--hard 60`: страховка на всё (большая работа: `--hard 120`).

Пока агент работает и пишет, он идёт без лимита до страховки.

Коды выхода: 0 готово; 10 idle; 11 tool-hung; 12 no-effect; 13 loop; 14 hard-cap; 20 ошибка agy; 21 упал без событий после автоповтора; 75 лимит или квота; 2 ошибка запуска.
- 10–14: проверить диск, продолжить ТОТ ЖЕ разговор командой из сводки (`--resume <id> --nudge "..."`, новое имя `<name>-r2`), бриф заново не писать. Два продолжения подряд без результата — «Соло» по CLAUDE.md.
- 20, 21: читать `<name>.stderr.txt` и `<name>.summary.json` (с limit), не весь поток.
- 75: профили сторож не переключает. Одной строкой владельцу, дальше п. 4 раздела 1 и «Соло».

Запасной путь, если сторож не запускается (остановка вручную, часового лимита нет):

```bash
agy --print="<промпт>" --model gemini-3.8-flash-high --add-dir "<абс. корень проекта>" --mode accept-edits --dangerously-skip-permissions
```

Общее для обоих путей:
- `--add-dir` + `--mode accept-edits` обязательны для записи. Без них agy пишет в свой scratch (`~/.gemini/antigravity-cli/scratch`) и рапортует успех.
- `--dangerously-skip-permissions` обязателен в headless: без него команды (и иногда чтения) авто-отклоняются, итог `jetski: no output produced`, rc=0. Флаг даёт неограниченный шелл — для ssh/деплоя/удалений действует server-safety.
- Промпт приклеен через `=`: `--print="..."` или `-p="$(cat файл)"`. Иначе флаг съедается как промпт. stdin не работает. Сторож делает это сам.
- Усилие зашито в id (`-high`), `--effort` не давать. Если `gemini-3.8-flash-high` пропал из `agy models` — сказать владельцу, id не угадывать (угаданный id = провал при rc=0).
- Функцию `agy` из Git Bash не пускать с `--output-format stream-json`: обёртка ищет «429» в тексте и даёт ложные срабатывания.
- В бриф включать: «пользуйся jcodemunch/jdocmunch/jev», «перечитай файл с диска и приведи итоговый фрагмент дословно». Для агентов, пишущих UI/тексты сайта, вставлять «Промпт-блок» из `design-library/ai-stamps.md`. Остальное (отчёт в файл за 30 с, запрет серверов и повторов, «не заявляй успех без вывода команды», кириллицу писать инструментами записи файлов, не командой оболочки) входит в хвост сторожа; с `--no-footer` писать вручную.
- В конце брифа: «запусти <проверка>; в отчёт: команда, код возврата, 5 строк хвоста; не запускал — так и напиши». Проверка по диску у оркестратора остаётся (самопроверка 20.10).

## 3. Параллельность

Число одновременных вызовов правилом не ограничено (решение владельца 20.10). Независимые куски раздавать параллельно, у каждого свой `--name` и файл вывода. Потолок на деле — виртуальная память Windows (20.10 пачка из 5 вызовов agy и субагента упала: rc=2 или 66, пустой вывод, «cannot allocate memory»). Сторож сам ставит свои запуски в очередь: не больше 3 одновременно и пока свободно не меньше 2 ГБ (`--max-slots`, `--min-free-mb`). Прямые вызовы `agy` и Claude-субагенты в очередь не входят: перед пачкой из 3 и более смотреть `FreeVirtualMemory` (`Get-CimInstance Win32_OperatingSystem`), при остатке меньше 3 ГБ запускать по 1–2. Вызов с rc=2 или 66 и пустым логом — сбой, а не тихий успех: проверить диск и перезапустить (сторож один повтор делает сам). Вывод упавшего вызова читать с limit (трасса Go весит 19 КБ). Бриф с многими проверками часами больше не режется: если агент встал, сторож остановит его по движению, продолжать через `--resume`.

## 4. Приёмка (rc=0 и отчёт агента — не доказательство)

- Всегда по диску: `git status` / `git diff --stat`, `wc -l`, чтение файла.
- `no output produced` или rc=1 — **сначала** смотреть состояние (работа часто уже сделана, падает на этапе тестов/сборки), потом решать о перезапуске. Слепой повтор рискует выполнить необратимое дважды; скрипты для agy делать идемпотентными.
- Приёмка: `jev_verify` против диффа/файла на диске. Источники расходятся — `jev_compare`.
- agy не ловит смысловые противоречия: ревью результата обязательно.
- Сборки, линтер, тесты прогоняет оркестратор сам.
