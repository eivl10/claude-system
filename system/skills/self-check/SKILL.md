# self-check

Нужна квитанция запуска. Перечитывание своей работы не проверка.

## Доказательство по видам работ

- Код: тесты, сборка, линтер проекта. Их нет — запусти изменённое (node --check, py_compile, скрипт на примере). Новый тест должен падать без правки.
- agy или субагент: файл на диске (Test-Path, размер), git diff --stat, сам перезапусти его проверку; jev_verify: отчёт против диффа. rc=0 и отчёт агента не доказательство.
- HANDOFF, README, доки: Test-Path по каждому пути из текста; jev_verify: утверждения документа против git status и листинга.
- Деплой: хеш локально и на сервере, HTTP-код страницы.
- UI и тексты сайта: jev_review по промпт-блоку ai-stamps; прод-UI скриншоты на 2–3 ширинах.
- Пояснение или ответ на вопрос: второго прохода нет. Факт о коде только из прочитанного в этом ходе (файл:строка), остальное «не проверял».

## Порядок

1. Пункты запроса — из слов владельца.
2. На каждый пункт одна проверка: команда, код возврата, до 5 строк вывода.
3. Красное или пункт не закрыт — правь только это, повтори ту же проверку. Не больше 2 кругов, дальше «Не проверено».
4. Зелёное — стоп. Улучшений не искать, прошедшее не трогать (слепой повторный проход портит верное).

## Крупное (2+ файла, Spec-First, прод)

agy Flash получает дифф и пункты запроса. Задача: таблица «пункт → есть/нет → строка», не «найди ошибки». Каждую находку подтвердить запуском. LLM-судья не арбитр правоты.

## В ответе

- Проверено: <команда> → <итог>
- Не проверено: <что> — <почему>

Строки пиши простыми словами (правило ponyatno): сначала итог, команда после. Без запуска в этом ходе «проверено» не писать.

## Не входит

«Подумай ещё раз» без запуска; LLM-судья как арбитр; принудительный advisor; проверки на вопросах; фиктивные команды (echo, ls) ради хука.
