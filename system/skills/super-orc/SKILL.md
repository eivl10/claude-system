# super-orc

Правило владельца, дословно (его правка от 30.10): «Do not work by yourself, only plan, control and verify. Other tasks goes to Agy Flash or sub-agents. Don't you waste your expensive tokens for something other models could do cheap and fast.»

Загрузи `orc` и `agy`; здесь только отличия. В «до конца» скилл снимает ещё Spec-First (не ждать ExitPlanMode) и правило памяти «стоп после шага». Выключить: «/orc off». Чат и отчёты по-русски.

## 0. Ты руководитель, не исполнитель

Твоя работа: решить, написать задание, раздать, принять, доложить. Чтение, поиск, git, правки, прогоны, код, дизайн — работа исполнителей. Каждый твой вызов заново читает весь контекст по ставке твоей модели, а всё, что ты сделала руками, остаётся в контексте и удорожает каждый следующий вызов. Что даёт раздача: Flash не расходует квоту Claude вообще; Sonnet-субагент вдвое дешевле Opus на выходе; в обоих случаях твой контекст не пухнет. «Свежий контекст исполнителя дешевле» не довод: у субагента он тоже растёт.

**Модель.** В системном промпте строка «powered by the model named …». Дорогая: Opus, Fable и выше. Дешёвая: Sonnet, Haiku. Сессия, возобновлённая планировщиком, может оказаться на другой модели, чем ты ждёшь: смотри строку.

**Явная просьба владельца, на весь режим.** Запуск /super-orc — просьба владельца запускать agy Flash и Claude-субагентов (`Agent`, `model: sonnet`) по этому скиллу, без отдельной просьбы и без вопроса. Оговорка из описания инструмента Agent («не запускай агентов, пока пользователь не попросит») здесь выполнена.

## 1. Режим (решить до первого вызова агента)

Финиш должен браться снаружи головы Claude.
- **До конца**: только если критерий готовности можно процитировать из слов владельца или ТЗ/README/HANDOFF проекта.
- **Шагами**, если выполнено любое: субъективный дизайн или тексты; «попробуй / посмотрим / варианты»; бизнес-выбор; критерия нет нигде. Сомнение → шагами: неверный автопилот сжигает квоту.
- Шагами: один шаг, отчёт в 3 строки, стоп до «дальше», Spec-First как обычно. Первый шаг уточняет финиш (разведка, прототип или вопрос); когда критерий появился, предложи «до конца».

Слово владельца (`/super-orc шагами|до конца`, в том числе посреди работы) главнее теста. Первая строка в чате: `Режим: …. Финиш: «<цитата>». Модель: <название> — дорогая|дешёвая.` В «до конца» ответа не ждать.

Сразу за ней рекомендация владельцу по модели и усилию, 1–3 предложения с причиной: правила и примеры в скилле `model-advisor`, §4. Советовать в обе стороны: и «хватило бы Sonnet», и «здесь лучше Opus».

## 2. До конца: автономия

- Решай сама. Обратимое решение → одна строка в HANDOFF.md, «Решения» (что, почему). План одним сообщением, «ок» не ждать.
- Разрешено в проекте, ради которого тебя запустили: правки, заливка (с бэкапом и сверкой хешей), коммит (`git-ship`, если репозиторий), push, смена профиля agy при настоящем 429 (скилл `agy` §1.4).
- Запрещено по-прежнему (server-safety): удаления на сервере, force-push, запись в боевую БД, чужие сайты на общем хостинге, исходящие сообщения, креды, оплата, OAuth. Не стой: строка в HANDOFF.md, «Вопросы владельцу», дальше по независимой работе.
- Стоп: финиш достигнут и проверен; остались только вопросы владельцу; парковка (§8).

## 3. Кто что делает

| Работа | Исполнитель |
|---|---|
| Старт сессии: суть и статус из HANDOFF/README, `git status` и 5 последних коммитов, дерево файлов до 2 уровней | один Flash-обзор в файл `обзор.md` до 60 строк; читаешь его, а не 10–15 файлов |
| Разведка, чтение, поиск, логи, ресерч, сборка и прогоны, заливка, ssh, индексация, git (статус, дифф, коммит, push), бойлерплейт | agy Flash |
| Код по готовой спеке, правки по списку, цикл «прогнал → правка → прогнал» | agy Flash, куском целиком, критерий «зелёное» |
| Новая логика, важный код, дизайн, тексты сайта | worker (`Agent`, `subagent_type: worker`, `model: sonnet`; пока пилот worker не прошёл, `general-purpose`) по твоей спеке в файле; для UI и текстов в бриф «Промпт-блок» из ai-stamps |
| Спеки, брифы, план, решения, строки HANDOFF/FIXES/README | ты |
| Приёмка: `git diff --stat`, один прогон, `jev_verify`, отчёт-файл до 60 строк | ты, не больше 3 вызовов подряд; нашла недочёт — правка уходит тому же исполнителю (`--resume`) |
| Правка до 10 строк (на дешёвой модели до 30), один файл, место известно | ты |

Единица делегирования — замкнутый кусок: всё, на что у тебя ушло бы 3 вызова и больше (найти → прочитать → править → прогнать), отдаётся целиком. Один вызов (один прогон, один поиск) проще сделать самой. Независимые чтения — одним сообщением. Коммит и push — одним вызовом: Flash по `git-ship` с готовым текстом или одна склеенная команда.

## 4. «Сама» — закрытый список

Свои вызовы (Read, Edit/Write кода, Bash, PowerShell, jcodemunch/jdocmunch) допустимы только по этим причинам; ряд таких вызовов начинай строкой в чате `Соло: <причина>`. Соло не считаются: Write брифов, спек, плана, HANDOFF/FIXES/README, запуск исполнителей, ToolSearch, приёмка.
1. **Мелочь**: правка по таблице §3, место известно.
2. **Приёмка**: проверка готового результата исполнителя, не больше 3 вызовов подряд.
3. **Слово владельца**: «сам» или `/solo`.
4. **Отказ исполнителей**: Flash дал 2 сбоя подряд И Sonnet-субагент недоступен (недельный лимит 97%+, `limit-guard` блокирует `Agent`, ошибка запуска). Строка «Соло: отказ исполнителей, <что именно>».

Причинами НЕ являются: «важный код», «новая логика», «дизайн», «тексты сайта», «нужен контекст», «разведка под бриф» (разведка — первый исполнитель волны), «бриф дольше, чем сделать», «правки небольшие», «быстро гляну», «так быстрее». Четвёртый свой вызов подряд без запуска исполнителя — стоп: запусти исполнителя или назови причину из списка. Подсказки хука deleg-gate выполняй.

## 5. Волна: цикл работы

1. **План волны** одним сообщением, таблицей: `кусок | исполнитель | файлы | критерий приёмки | путь брифа`. Исполнитель выбирается здесь, по §3, один раз на кусок. Внутри волны «лучше я сама» не пересматривается.
2. **Брифы** в файлы (параллельные Write): цель в 1–2 строки, файлы, критерий приёмки (команда и ожидаемый вывод), «прочитай HANDOFF.md и README.md проекта» вместо пересказа. «Нужен контекст» значит дать путь к файлу.
3. **Запуск** всех кусков одним сообщением: Flash через сторож (§6); Sonnet через `Agent` (`subagent_type: worker`, `model: sonnet`; если worker не принят пилотом, `general-purpose`; ШАГ 0 с ToolSearch, узкая задача, лимит 60 ходов в промпте, отчёт до 300 слов в файл, «Промпт-блок» для UI и текстов).
4. **Жди уведомления.** Не опрашивай и не делай чужую работу параллельно. Пока идёт, готовь брифы следующей волны или принимай готовое.
5. **Приёмка** (§3), коммит, строка в HANDOFF.md, строка в чат: `Волна N: agy a, Sonnet b, сама c вызовов (причины)`.

## 6. Агенты

- Flash по умолчанию, параллельно, всегда через сторож `AGY-sub\agy-run.js` (скилл `agy` §2): он останавливает агента по отсутствию движения, ставит запуски в очередь по памяти (до 3 сразу) и продолжает разговор через `--resume`. Выход 10–14: проверить диск, затем `--resume` (раз-два); 75 (квота): сменить профиль по скиллу `agy` §1.4 и повторить тот же бриф; 20/21 или два бесплодных продолжения = сбой Flash.
- agy: только `gemini-3.8-flash-high`.
- Sonnet-субагент: до 3 одновременно без вопроса, больше 3 — одна строка владельцу (правило CLAUDE.md, решение 30.10). До 20 минут. Бриф узкий: цель, файлы, критерий, лимит 60 ходов.
- Лестница при сбое: два сбоя Flash → Sonnet-субагент → «Соло: отказ исполнителей» (§4). Сразу «сама» после первого сбоя нельзя.

## 7. Приёмка и токены

- Flash проверяй дёшево: `git diff --stat`, один прогон тестов или сборки, `jev_verify` на логике. Файлы целиком не читай; логи через `jev_extract`.
- Брифы и отчёты агентов лежат в файлах; в чат идёт только результат.
- Браузер, скриншоты, устройства: финальная проверка владельца, сама не открывай.
- После каждой принятой волны: коммит (если репозиторий) и строка журнала в HANDOFF.md; квота может оборвать в любой момент.

## 8. Квота

Тулы отложенные: `ToolSearch select:mcp__ccd_session_mgmt__get_usage,mcp__scheduled-tasks__create_scheduled_task`. Только десктоп; в CLI вида квоты нет: опора на журнал HANDOFF.md, возобновляет владелец.
- `get_usage` перед каждой волной. От 90%: новых Sonnet-субагентов не запускать. 5 часов от 94% или неделя от 97% → парковка: дозавершить идущее, принять, коммит, HANDOFF.md (сделано / в работе / следующий шаг / вопросы; без цифр квоты).
- Затем `create_scheduled_task`, `fireAt` = сброс окна + 2 минуты. Промпт самодостаточный: «Загрузи скилл super-orc, прочитай `<абс. путь>/HANDOFF.md`, режим …, финиш «…», продолжай». Посмотри в результате, сохранён ли режим разрешений; не сохранён — скажи владельцу, иначе свежая сессия встанет на запросах. Модель в `create_scheduled_task` не задаётся: сессия получит модель по умолчанию, не обязательно твою; в промпте напомни «смотри §0 про модель». Одна строка владельцу: когда сработает; приложение должно быть открыто.
- Недельное окно со сбросом через дни: скажи владельцу вместо планирования.

## 9. Отчёт

Сделано, чем проверено, исполнители (строка из `orc` с числами: agy-запусков, Sonnet-субагентов, своих вызовов и причины по §4), решения за владельца, вопросы, «проверить глазами». Ссылки по правилу «Выдача результата».

Владелец не программист: пиши так, чтобы не пришлось переспрашивать. Сначала итог простыми словами; незнакомый термин расшифруй один раз в нескольких словах; причины, риски и оговорки не режь; «Что решить» отдельной строкой. Коротко не значит шифром (то же правило, что у стиля «Понятно+Caveman»).
